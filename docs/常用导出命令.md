# 常用导出命令

本文档记录当前已配置游戏的常用资源导出命令。运行前先进入仓库根目录：

```powershell
cd D:\misutime\UnrealExporter
```

## NTE

```powershell
just nte
```

```powershell
dotnet run --project UnrealExporter nte-all-assets
```

- 配置文件：`configs/nte-all-assets.json`
- 输出目录：`F:\UE5-Assets\nte-all-assets`
- Mapping：`mappings/NevernessToEverness.usmap`
- 默认并发：`6`，重型导出并发 `2`

### NTE 可复用素材库候选导出

```powershell
just nte
```

```powershell
dotnet run --project UnrealExporter nte-all-assets
```

- 配置文件：`configs/nte-all-assets.json`
- 输出目录：`F:\UE5-Assets\nte-all-assets`
- 范围：当前本机 NTE 大库导出，扫描 `HT/Content` 下 `.uasset`，通过排除规则过滤测试、占位、碰撞、代理、影片等噪音
- 模型：`gltf`
- 贴图：`png`，后处理统一进入 `Textures/_Shared` 并优先硬链接复用
- 动画：`ueanim`，失败但有可用事实的动画写 metadata 侧车
- 关系：开启 `generateSourceIndex`、`generateLibraryIndexes`、`autoExportReferencedAssets`
- 绑定原则：模型动画关系只来自 UE Skeleton、组件引用、动画片段等确定性证据；同 Skeleton 兼容动画可验证，但不按名称硬猜

注意：独立动画资产是 `.ueanim`；formal GLB 通过 `--export-ue-animation-glb` 从源模型和源 `.ueanim` 生成，生成时才写入 glTF TRS 动画通道。

## Fortnite

```powershell
just fortnite
```

```powershell
dotnet run --project UnrealExporter fortnite-useful-assets
```

- 配置文件：`configs/fortnite-useful-assets.json`
- 示例配置：`configs/examples/fortnite-useful-assets.json`
- 输出目录：`output/fortnite-useful-assets`
- Mapping：`mappings/FortniteGame.usmap`
- 默认并发：`12`
- 默认会从 FortnitePorting API 自动获取 AES、dynamic AES keys 和 mappings，并启用 Fortnite on-demand chunk 读取。
- Fortnite 40.40 / UE 5.8 需要读取 cooked mesh 里的 mobile MinLOD 字段，本工具已在 Fortnite 模式自动开启，否则 GLB 会表现为全部失败或空模型。

## 素材库后处理

刷新共享贴图、模型/动画关系、健康报告和 SQLite 索引：

```powershell
dotnet run --project UnrealExporter -- --postprocess-library F:\UE-Assets\nte-useful-assets --dedupe-textures
dotnet run --project UnrealExporter -- --postprocess-library F:\UE-Assets\batman-models --dedupe-textures
```

当前 NTE 大库：

```powershell
dotnet run --project UnrealExporter -- --postprocess-library F:\UE5-Assets\nte-all-assets --dedupe-textures
```

把导出失败但含曲线、通知或 Montage/Composite 片段的 UE 动画标记为 SQLite metadata 行：

```powershell
dotnet run --project UnrealExporter -- --materialize-animation-metadata F:\UE-Assets\nte-useful-assets
dotnet run --project UnrealExporter -- --materialize-animation-metadata F:\UE-Assets\batman-models
```

当前 NTE 大库：

```powershell
dotnet run --project UnrealExporter -- --materialize-animation-metadata F:\UE5-Assets\nte-all-assets
```

物化 metadata 默认只更新 `export_events.db` 里的 `asset_catalog` 和 `animation_bindings`，不会写 `.ueanim.metadata.json` 侧车。需要人工排查侧车时加 `--debug-json`。物化后需要再运行一次 `--postprocess-library --dedupe-textures`，让 `library_index.db` 和健康报告同步到最新状态。metadata 动画只用于检索和后续曲线/容器动画支持，不会进入默认可播放动画候选。

合成 `.ueanim` 预览时，浏览器默认使用 SQLite 报告：

```powershell
dotnet run --project UnrealExporter -- --preview-ue-animation --model <model.glb> --animation <anim.ueanim> --output <preview.glb>
```

默认会在输出旁生成 `<preview>.preview_validation.db`。需要指定路径时使用 `--report-db <preview_validation.db>`；只有人工排查时才使用 `--report <debug.json>`。

正式导出“模型 + 单动画”GLB：

```powershell
dotnet run --project UnrealExporter -- --export-ue-animation-glb --model <model.gltf-or.glb> --animation <anim.ueanim> --output <formal.glb> --report <formal.export.json>
```

正式 GLB 写入 glTF node `translation` / `rotation` / `scale` channels；不要把它当作独立动画资产写回 `relation_animations`。

## 已拆分的后处理项目

素材浏览和 Humanoid 后处理已经拆出当前仓库：

- `D:\misutime\AssetLibraryBrowser`：通用素材库浏览器、缩略图、F3D/preview 浏览。
- `D:\misutime\HumanoidRetargeter`：Unity Humanoid FBX、Godot GLB 辅助包、ARPG Humanoid 标准化、重定向和视觉门禁。

当前仓库只维护 Unreal 游戏素材提取、`.ueanim` 导出、UE animation preview/formal GLB 生成，以及 `asset_library.json` / `library_index.db` 输出。

## 备注

- `configs/*.json` 是本机实际运行配置，默认不提交 git。
- `configs/examples/*.json` 是可提交的示例配置，需要时复制到 `configs` 后再运行。
- 当前导出策略优先保证资源精简和 GLB 可识别性，少量有用资源优先于大量噪音资源。
